# Mobile production launch inventory

Scope: production `src/server` imports of `node:child_process` and managed MCP
configuration. `composition.contracts.ts` is a test harness. Mobile has no
production `mkdtemp(tmpdir())` allocation. Managed scratch is centralized in
`platform/scratch/filesystem-session-scratch.ts`; see the
[version 1 contract](session-scratch-contract.md).

Regression evidence covers real app-server and descendant environments for two
sessions/recovery, provider mappings, native mktemp/Node/Python from nested cwd,
discovery scrubbing, shared Kimi lease and host guardian's actual child environment.
Existing runtime/browser/provider/retrieval/plan-status/policy suites exercise the
wiring. Generated executable fixtures use workspace tmp rather than assuming an
executable `/tmp` mount. The inventory classifies Mobile-created directories;
launcher-created tool scratch follows the same contract in its owning repository.

Unrelated launches remove all four owning-session values only when the context
variable is present; ordinary operator temporary roots survive when it is absent.
Service release requires bounded confirmation that the entire owned process group
is absent. Descendant-shutdown, timeout and exit75 regressions cover that boundary;
unknown groups remain protected rather than being reported released.
