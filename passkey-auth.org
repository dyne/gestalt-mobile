- Effort :: Medium
- Goal :: Define the single-owner authorization model, stable WebAuthn relying-party contract, and user-wide persistence boundary that every Gestalt Mobile process on the host shares.
- Notes :: Start from the existing Node 24, Fastify 5, Svelte 5 application: relay state currently lives in a per-workspace SQLite database, =--host= defaults to =127.0.0.1=, and the README explicitly says there is no built-in authentication or TLS. This milestone must not protect routes yet; it produces the contracts and adapter used by the next milestone. Use the ubiquitous terms =LocalOwner=, =AuthorizedDevice=, =DeviceNickname=, =PasskeyCeremony=, =EnrollmentTicket=, and =AuthorizationSession=. There are no accounts, usernames, roles, passwords, emails, recovery codes, or workspace-specific grants. One random, opaque WebAuthn user handle identifies the local owner, and every credential belongs to that owner. Store authorization independently of =--data-dir= at =~/.codex-gestalt/gestalt-mobile/auth.sqlite= (resolved from the injected home directory in tests), so different workspace roots and relay databases share it. The effective RP ID is the hostname of an explicit canonical public origin; different ports on that hostname remain compatible. A changed hostname is a deliberate migration boundary and must fail startup while credentials exist rather than silently stranding them. Follow current SimpleWebAuthn server/browser contracts, W3C WebAuthn origin/RP-ID validation, and exact expected-origin verification. Do not add an attestation metadata service or collect authenticator identity.
